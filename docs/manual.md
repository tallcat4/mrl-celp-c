## フレームの構成

40 ms のフレームを 20 ms の半分 2 つに分け、半分をさらに 10 ms(80 sample)のサブフレーム 2 つに分けます。

| 項目 | 単位 | ビット数 |
| --- | --- | --- |
| モード(LSF の移動平均予測の係数の組) | 半分 | 1 |
| LSF の 2 段ベクトル量子化(1 段 128 通り × 10 次、2 段 64 通り × 5 次 × 2) | 半分 | 7 + 6 + 6 |
| ピッチ(1/3 sample の分解能、20〜143) | サブフレーム | 絶対 8 / 差分 5 |
| 固定符号帳(パルスの形 2〜3 個の区分 0〜4、単位パルス 5 + 5 個の区分 5) | サブフレーム | 16 |
| ゲイン(ピッチ利得と、予測つきの符号帳利得の組、128 通り) | サブフレーム | 7 |

計 158 ビットを 20 バイトに LSB first で詰めます(上位 2 ビットは 0)。ビットの並びは `decoder/src/bits.c` にあります。
後半 2 つ目のゲインの下位 4 ビットの位置と、前半の絶対ピッチの下位 2 ビットの反転は、原本の注記どおり経験的に確かめた仮定です。

## デコーダ

jr-conventional-line-radio-receiver の `crates/jr-voice/src/celp`(commit `dfc7440`)を C99 に移植したものです。
16 ビット固定小数点 DSP(40 ビット累算器、小数乗算)の処理を `int64_t` で再現し、LSF とゲインの予測だけが単精度浮動小数です。
状態は 868 バイト、速度は Apple M5 で 1 フレーム 5.8 µs です。

```c
#include "mrlcelp.h"
static double mem[1024 / sizeof(double)];      /* mrl_decoder_size()(868)バイト以上、8 バイト境界 */
mrl_decoder *d = mrl_decoder_init(mem);
int16_t pcm[MRL_FRAME_SAMPLES];                /* 320 sample = 40 ms */
if (mrl_decode(d, payload20, pcm) != 0) { /* 上位 2 ビットが 0 でない(不正なフレーム) */ }
```

```bash
decoder/mrl2wav in.mrl out.raw          # 見出しなしの PCM
decoder/mrl2wav in.mrl out.wav --pre    # 出力フィルタの前の合成(評価用)
```

- 自分のビルドシステムに組み込むときは `decoder/src/*.c` と `decoder/include/` を加え、**`-ffp-contract=off`** でコンパイルします(積和を融合すると、ゲインと LSF の予測の丸めが原本と変わります)。
- `-DMRL_MAC16` を付けると、Xtensa(ESP32 など)の MAC16 の 40 ビット累算器で積和をします。
- 40 ビット累算器の巻き戻しは、値がその範囲に収まることが分かる所では省いています(結果は同じ)。
- `logf` / `expf` はプラットフォームの libm を使います(原本と同じ)。libm が違うと、ごくまれに PCM が ±1〜2 違うことがあります。参照ベクトルは macOS(arm64)で作りました。
- `decoder/src/tables.c` は原本の表から自動生成したもので、手で編集しません。
- jr-voice の学習済みの後処理(先読み 280 ms)は含みません。

### 三菱型の復号(`--mpf`)

[mcelp-codec](https://github.com/soltia48/mcelp-codec)(三菱 CELP、3.6 kbps、MIT)のデコーダは、フレームの構成、CELP 本体の処理、出力フィルタ(係数 `7472, −22381, 22381, −7472` / `−23033, 21666, −6815`、倍率 `19661`)が MRL-CELP と同じで、出力フィルタの直前に適応ポストフィルタがあります。
jr-voice の CELP 本体(このデコーダ)にはこのポストフィルタが無いので、本来の MRL-CELP のデコーダにもあったと推定して、`src/postfilter.rs` と `src/ltp.rs`(commit `1ffc2f5`)を `decoder/src/mpostfilter.c` に移植しました。

```bash
decoder/mrl2wav in.mrl out.wav --mpf                              # 本体 → 三菱のポストフィルタ → 出力フィルタ(固定小数点)
decoder/mrl2wav in.mrl out.wav --enhance                         # --enhance の既定のポストフィルタもこれ(--postfilter=g729 で G.729 型)
```

- 短期:サブフレームの LSF を平らなバイアスへ 0.39 / 0.61 の度合いで寄せて分母・分子を作る(係数を γ 倍するのではなく LSF の領域で)。長期:ラグ ±1 と両側 7 位相、16 タップでの作り直し、原信号に 2/3 の重み。傾きの補正と AGC。
- 移植は mcelp-codec の関数との突き合わせをまだしていません(ビット一致は未確認)。
- 本物の MRL-CELP のデコーダにこのポストフィルタがあるかどうかは確かめようがなく、あくまで推定です。

### 聞きやすさ優先の復号(`--enhance`、ビット一致ではない)

パラメータの復号(LSF・ピッチ・固定符号帳・ゲイン)は上と同じで、その先を浮動小数でやり直します。バスポストフィルタのために出力は 160 sample(20 ms)遅れます(`mrl2wav` は最初の 160 sample を捨てて最後に足すので、入力と時刻がそろいます)。

```bash
decoder/mrl2wav in.mrl out.wav --enhance                 # 既定: 下の 1〜5・7・8(声の大きさの調整だけ切)、×0.5
decoder/mrl2wav in.mrl out.wav --enhance --lowcut=300    # 低域の膨らみを抑える EQ を足す
decoder/mrl2wav in.mrl out.wav --enhance --level         # 話者ごとの声の大きさをそろえる(--level=2000 で目標の rms)
# 段ごとに外す: --no-postfilter --no-antisparse --no-pitchenh --no-noiseenh --no-bass --no-limiter
# 位相分散をピッチ利得だけで判断: --antisparse-all、音量: --gain=0.5
```

```c
static double emem[16384 / sizeof(double)];          /* mrl_enhanced_size() バイト以上 */
mrl_enhanced *e = mrl_enhanced_init(emem, NULL);     /* NULL で既定。mrl_enh_config で段ごとに変えられる */
mrl_decode_enhanced(e, payload20, pcm);     /* 20 ms 遅れの 320 sample */
mrl_enhanced_flush(e, pcm);                  /* 最後に残りの 160 sample */
```

1. **浮動小数の励振・合成**:式は本体と同じです(補間フィルタ、ゲインの Q14 / Q13、LPC の Q12)。実データ(2026-11-03 の D4V1、1839 フレーム)では、クリップの無いフレームの出力が本体と 99 % の sample で ±22 以内に一致しました。違いが出るのは本体が飽和した 14 フレームだけです。
2. **音量 ×0.5 とソフトリミッタ**:同じ実データの合成は 16 ビットの約 2.4 倍(最大 77240、99.99 % 点が約 50000)まで振れ、本体ではそこで飽和して 191 sample がクリップしていました。×0.5 で 99.99 % 点がリミッタの効き始め(フルスケールの 70 %)に来ます。`--enhance` ではクリップは 0 です。
3. **適応ポストフィルタ**:既定は三菱 CELP 型(上の `--mpf` と同じもの。浮動小数の合成を ×0.5 して 16 ビットに収めて通し、×2 で戻す)。`--postfilter=g729` で G.729 型(長期:復号したラグ ±3 の整数ラグ、γp = 0.5。短期 A(z/0.55)/A(z/0.7)、傾きの補正 0.8、AGC)。実データの聴き比べでは三菱型の方がわずかに良く、自動の指標(倍音と雑音の比など)では差がありませんでした。
4. **位相分散**(AMR の anti-sparseness と同じ考え方):平らな振幅・決まった位相の巡回の全域通過で、エネルギーは変えません。4・7 は AMR-WB と同じく合成に使う励振だけに掛け、適応符号帳の記憶は本体と同じ励振で進めます(記憶を加工すると、無線機のエンコーダが合成による分析で想定した状態からずれていくため)。既定では、エネルギーの 85 % 以上が上位 10 sample にある疎なベクトルのうち、ピッチ利得が 0.9 未満のものだけに掛けます。
5. 出力のハイパスは本体の出力フィルタと同じ特性(約 150 Hz の 6 次、通過域 +1.6 dB)を浮動小数で掛けます。
6. **声の大きさの調整**(`--level`、既定では切)。受信機の AGC と同じ考え方で、声のある所の rms を約 0.4 s で追い、目標(既定 2000)にそろえます(−6〜+12 dB、無音は持ち上げない)。
   同じ実データでは、女性のターン(F0 が 240 Hz 以上の 8 ターン)が、ビット列のゲインの時点で男性より約 8 dB 小さく送られていました。一方、ビット列の LPC 包絡の明るさは男女でほぼ同じ(−19.5 / −19.2 dB)で、聞き取りにくさの主な原因は音量でした。`--level` でこの差は約 4 dB になります。
7. **ピッチ強調とノイズ強調**(AMR-WB):有声度 rv = (Ev − Ec)/(Ev + Ec)(適応・固定符号帳の寄与のエネルギー)から、固定符号帳の寄与を c(n) − 0.125(1 + rv)(c(n−1) + c(n+1)) にします。また、スペクトルの安定度 θ = 1.25 − Σ(ΔLSF[Hz])²/400000 と無声の度合いに応じて、符号帳ゲインを ±1.5 dB の範囲で前の値に寄せます(背景雑音のうねりを抑える)。
8. **バスポストフィルタ**(G.718 / EVS 型):e(n) = s(n) − (s(n−T) + s(n+T))/2(T は復号したラグ)を 1 kHz の低域通過に通し、ピッチ周期の両側の相関に応じた α(0〜0.25、`--bass=` で上限を変更)で引きます。1 kHz より下の倍音の間の雑音を消します。上限 0.5 では、有声音の 1 kHz より下の倍音と倍音の間の比が 31.8 dB(素の CELP は 19.7 dB)まで上がり、ブザーのような声に聞こえました(0.25 で 27.3 dB)。

実データで確かめられたこと:1・2 で飽和が無くなる(クリップ 191 → 0)。8 で、有声の所の 1 kHz より下の倍音と倍音の間の比が、女性 25.7 → 34.8 dB、男性 16.9 → 20.9 dB(ただしこれはフィルタと同じ復号したピッチで測った値)。7 で、静かな所の 10 ms ごとのレベルの揺れが 2.13 → 1.94 dB。
これらは雑音が減ったことは示していますが、聞きやすくなったことの証明ではありません。3〜8 は CELP の規格で定番の処理で、このコーデックでの良し悪しは聴いて決めてください。

### 帯域拡張(`--wideband`、16 kHz で出力)

どの復号にも付けられる後処理です(`decoder/src/widen.c`)。4 kHz より上はビット列に無いので、**声としてもっともらしい高域を作って足します(本物の高域ではありません)**。

```bash
decoder/mrl2wav in.mrl out.wav --enhance --level --wideband        # 16 kHz の WAV
decoder/mrl2wav in.mrl out.wav --enhance --level --wideband=2.5    # 高域を強めに(既定 1.5)
```

```c
static double wmem[8192 / sizeof(double)];
mrl_widen *w = mrl_widen_init(wmem, NULL);
mrl_widen_process(w, pcm80, wide160);   /* 8 kHz の 80 sample → 16 kHz の 160 sample、mrl_widen_delay()(112)sample 遅れる */
```

1. 8 → 16 kHz(Kaiser 窓の 97 タップの低域通過、3.8 kHz)
2. 高域の音源:1.2〜3.8 kHz の帯域を 2 乗(x²)したもの。和の周波数(2.4〜7.6 kHz)が 4 kHz より上に倍音を作り、有声音では F0 の間隔の倍音が続く。有声音にも雑音を 10 %(パワー)混ぜる(混合励振。倍音だけだとロボット感があった)。無声音の度合いに応じて雑音を増やす
3. 大きさ:3〜3.8 kHz 付近と同じ密度 × 1.5 に、傾きの係数 (1 − r1/r0)²(AMR-WB の高域と同じ考え方を 2 乗、約 20 ms でならす)を掛ける。母音ではほぼ足さず、摩擦音では大きくなる。
   2.5〜3.8 kHz のエネルギーは直近 30 ms の中央値を使い、高域の大きさは上がるときは約 30 ms、下がるときは約 6 ms で追う(元の音の 1 ブロックだけの跳ねを高域に広げない)
4. 上へ行くほど弱くなる傾き(1 次の低域通過、4.5 kHz)を付け、3.9〜6 kHz の帯域通過に通して足す

既定は、実データ(D4V1)の聴き比べで、パチパチ感・こもり・ロボット感の釣り合いが一番良かったものです。試したことと、聴いて分かったこと:
- 雑音だけの音源(`--wb-noise`):クリアにはなるが、ザラつき・パチパチ感があった。包絡を 1 kHz で平滑すると、ピッチのパルスごとに雑音のかたまりができた
- 全波整流を 2.5〜3.8 kHz からにすると、和の周波数が 5〜7.6 kHz にしかできず、4〜5 kHz が空いてこもった(5〜6 kHz が 4〜5 kHz より 11.8 dB 大きかった)。元の帯域を 1.2 kHz からにして直した
- 7 kHz まで足すと高いパチパチ感が残り、6 kHz までにすると減った
- パチパチ感は、波高率・尖度・孤立したかたまり・サブフレームの境目のどの指標でも捉えられず、聴き比べで決めた

`--wb-noise` `--wb-mix`(有声 = 全波整流、無声 = 雑音)`--wb-abs`(x² でなく |x|)`--wb-aperiodic=` `--wb-band=3900,6000` `--wb-shape=150,2,4500`(包絡の平滑 Hz、係数のべき、傾き Hz)で変えられます。
実データでは、4 kHz より下は帯域拡張の前と一致し(8 kHz に戻すと相関 0.999998)、有声音の 4.2〜6 kHz の倍音と倍音の間の比は、雑音の音源の 0.1 dB に対して 2.5 dB(雑音を混ぜない全波整流では 8.9 dB)でした。

## エンコーダ

本物の(無線機の)エンコーダの手順は公開されていないので、デコーダのビット列の意味と状態遷移に合わせて、分析による合成(A-b-S)の CELP として作りました。
デコーダの状態の処理(`decoder/src/core.h`)で状態を進めるので、エンコーダとデコーダの状態は常に一致します。

```c
#include "mrlcelp_enc.h"
static double mem[10240 / sizeof(double)];          /* mrl_encoder_size() バイト以上、8 バイト境界 */
mrl_encoder *e = mrl_encoder_init(mem, NULL);       /* NULL で既定の設定 */
uint8_t payload[MRL_FRAME_BYTES];
if (mrl_encode_push(e, pcm320, payload)) send(payload);   /* 320 sample ずつ。1 つ前のフレームが出る(先読みのため) */
if (mrl_encode_flush(e, payload)) send(payload);          /* 最後のフレーム。半端な最後のフレームは 0 で埋めて push する */
```

- 遅れはフレーム 40 ms + 先読み 10 ms。状態は 9.5 KB(と、探索に使う static の 25 KB)。速度は Apple M5 で 1 フレーム 92 µs です。
- `mrl_enc_config`(`mrl_enc_default_config` で既定値)で探索の幅を変えられます。既定値は、評価用の別の 130 発話で品質をほとんど落とさずに絞った値です。
- 組み込むときは `encoder/src/encoder.c` と `encoder/include/`、デコーダの `src/*.c` と `include/`・`src/` を加えます。エンコーダは積和を融合してよく、ESP32 では速くなります。

品質:テスト用の 32 発話(LibriSpeech test-clean の英語 24 発話、macOS の `say` の日本語 8 発話)で、PESQ(P.862 狭帯域)2.87、合成の SNR 9.6 dB です。
研究用の Python 版では、最初の試作が PESQ 2.74、ビーム探索つきの重い設定が 3.07 でした。ただ、この程度の差は聴き比べではほとんど区別できませんでした。

手順(半フレーム 20 ms ごと):
1. 線形予測:サブフレームの中心に 240 sample の窓(後半は 10 ms の先読み)、Chebyshev 多項式の根の探索で LSF
2. LSF の量子化:デコーダの移動平均予測を裏返した目標に対して 1 段・2 段の上位を組み合わせる。後半の LSF と前半(前の半フレームとの中点)の LSF の両方で誤差を測る
3. 開ループのピッチ:聴感の重み付けをした音声の正規化相関

サブフレーム 10 ms ごと:

4. 聴感の重み付け W(z) = A(z/0.94)/A(z/0.6) をかけた目標
5. ピッチ:整数のラグは、分母を補間フィルタを通した励振の再帰(G.729 と同じ)、分子を正確な適応符号帳で比べ、小数は前後の得点が高い側だけ調べる
6. 固定符号帳:パルスの形をフィルタに通したものを位置をずらして使い、相関の大きい位置だけ組み合わせる
7. 上位の候補を 128 通りのゲインと比べ、選んだものだけ正確な符号ベクトルでゲインを選び直す
8. デコーダの状態を進める

## 誤り訂正

無線の 1 フレーム(384 ビット = 48 バイト、MSB first)と音声のペイロード(20 バイト)を相互に変換します。
jr-conventional-line-radio-receiver の `crates/receiver-core/src/voice_frame.rs` と `coding.rs`(commit `9945870`)を C99 に移植したもので、復号の結果は原本とビット一致します。
コーデックとは独立していて(`fec/`)、malloc も libm も使いません。

384 ビットの中身:
- 128 ビットの区間が 3 つあり、それぞれ先頭 16 ビットが同期の符号(`0x3d22`、`0xe867`、`0xe867`)、残り 112 ビット × 3 がデータです。
- データの 336 ビットは、PN 9 段(x⁹ + x⁵ + 1)のスクランブルをかけた 42 バイトの語です。
- ペイロードの先頭 78 ビットには CRC-8 を付け、畳み込み符号(拘束長 9、パンクチャ、176 ビット)で守ります。残り 80 ビットは符号なしです。
- 語の 28〜41 バイトは、モード(`0x80` と 0/1)、CRC-16、Reed-Solomon のパリティ 6 バイトです。

復号の手順(原本どおり):
1. **硬判定**(`mrl_fec_decode`):畳み込み符号の逆算 → RS で末尾を訂正 → Viterbi → 末尾を作り直して受信と突き合わせる(合同の訂正)。受理には CRC-8 と末尾の 64 ビットの一致が要ります。
2. **軟判定**(`mrl_fec_decode_soft`):硬判定がだめなら、ビットごとの信頼度で重みをつけた Viterbi を使います。末尾は、信頼度の低いバイトを 0・2・4・6 個消失として扱う RS の訂正を試します。

```c
#include "mrlfec.h"
uint8_t envelope[MRL_ENVELOPE_BYTES], payload[MRL_FRAME_BYTES];
int corrected;
/* 受信:confidence は 384 ビットそれぞれの信頼度(0〜255、復調器の出力)。無ければ NULL */
if (mrl_fec_decode_soft(envelope, confidence, payload, &corrected) == 0) mrl_decode(d, payload, pcm);
/* 送信:alternate は語の 33 バイト目(0 か 1) */
mrl_fec_encode(payload, 0, envelope);
```

- スタックは硬判定で約 5 KB、軟判定で約 6.5 KB、コードは約 12 KB(x86-64、gcc -O2)です。
- 復調器、384 ビットの同期(フレームの位置合わせ)、データのフレーム(RS (42, 30) と CRC-16)は含みません。
- テスト(`make -C fec test`)は 8000 フレーム(誤りなし、散らばった誤り、当てにならない信頼度、バースト、乱数)を原本と同じ乱数で作り、硬判定と軟判定の結果のハッシュを原本の値と比べます。参照の作り方は `fec/tests/reference/README.md` にあります。

## MCU での実測

テストの音声(LibriSpeech の 4.8 秒、120 フレーム)を符号化してデスクトップと同じフレームか、そのフレームを復号した PCM のハッシュが同じかを確かめ、
1 フレーム(40 ms)あたりのサイクル数を数えます(`encoder/tests/mcu/mcu_test.c`)。

| ボード | エンコーダ | デコーダ | 合計(CPU の割合) |
| --- | --- | --- | --- |
| Arduino Portenta H7(Cortex-M7、400 MHz) | 270 万サイクル(最大 283 万) | 22 万 | 292 万(18%) |

どちらもフレームは 120/120 がデスクトップと同じで、PCM もビット一致しました。

```bash
encoder/examples/esp32/run.sh /dev/cu.usbserial-XXXX   # ESP-IDF 5.4。MRL_PROFILE=1 で段階ごと、MRL_MICRO=1 で部品ごと
encoder/tests/mcu/portenta/run_portenta.sh             # arduino-cli と arduino:mbed_portenta、pyserial
encoder/tests/mcu/update_expected.sh                   # エンコーダを変えたら期待値を作り直す
```

ESP32 で効いたこと(最初の版の 1750 万サイクルから 320 万へ):
- 探索の幅を、評価用の発話で品質を見ながら絞る(開ループの 2 つ目のピッチ候補は、調べない方が品質も良かった)
- ピッチの分母は再帰、分子だけ正確に。符号 ↔ ラグは表と算術式で
- 固定符号帳の相関は H^T x と形の内積で。ゲインは近似で比べ、選んだものだけ正確に
- 割り算を避ける(ESP32 の浮動小数の割り算はソフトウェア)。内積の形にして累積を 4 本に分ける
- エンコーダだけ積和を 1 命令(`-ffp-contract=fast`、`madd.s`)にする
- デコーダの固定小数点:巻き戻しの省略と MAC16(ビット一致のまま、63 万 → 38 万サイクル)
- コードと表を内部 RAM に置く
