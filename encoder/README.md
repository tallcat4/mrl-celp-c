# encoder — 改良型 RL-CELP のエンコーダ(オリジナル実装)

本物の(無線機の)エンコーダの手順は公開されていないので、デコーダのビット列の意味と状態遷移に合わせて、分析による合成(A-b-S)の CELP として作りました。
出すビット列は [`../decoder`](../decoder/README.md)(原本とビット一致)でそのまま復号できます。
デコーダの状態の処理(`../decoder/src/core.h`)をそのまま使って状態を進めるので、エンコーダとデコーダの状態は常に一致します。

- **品質**:テスト用の 32 発話(LibriSpeech test-clean の英語 24 発話、macOS の `say` の日本語 8 発話)で、PESQ(P.862 狭帯域)2.87、合成の SNR 9.6 dB です。
  研究用の Python 版では、最初の試作が PESQ 2.74、ビーム探索つきの重い設定が 3.07 でした。この C 版は、マイコンで動くように探索を絞ったものです。
  なお、PESQ で 0.3 程度の差は、聴き比べではほとんど区別できませんでした。音の性格は、エンコーダよりデコーダ(4 kbps の CELP、ポストフィルタなし)で決まっていると考えています。
- **軽さ**:浮動小数(float)。動的メモリ確保はなく、状態は 9.5 KB(と、単位パルスの区分の探索に使う static の 25 KB)です。速度は Apple M5 で 1 フレーム 92 µs です。
- **遅れ**:フレーム 40 ms + 先読み 10 ms。

## ビルド
```
make            # libmrlenc.a、wav2mrl(デコーダの libmrldec.a も作る)
make test       # テストの音声を符号化して、期待のフレームと比べる
```
自分のビルドシステムに組み込むときは、`src/encoder.c` と `include/`、デコーダの `src/*.c` と `include/`・`src/` を加えます。
デコーダのファイルは `-ffp-contract=off` でコンパイルしてください(エンコーダは融合してよく、ESP32 では速くなります)。

## 使い方
```
./wav2mrl in.wav out.mrl      # 8 kHz・16 ビット・モノラル(44 バイトの見出しの WAV、または見出しなしの PCM)→ 20 バイト/40 ms
```
```c
#include "mrlcelp_enc.h"
static double mem[10240 / sizeof(double)];          /* mrl_encoder_size() バイト以上、8 バイト境界 */
mrl_encoder *e = mrl_encoder_init(mem, NULL);       /* NULL で既定の設定 */
uint8_t payload[MRL_FRAME_BYTES];
if (mrl_encode_push(e, pcm320, payload)) send(payload);   /* 320 sample ずつ。1 つ前のフレームが出る(先読みのため) */
...
if (mrl_encode_flush(e, payload)) send(payload);          /* 最後のフレーム。半端な最後のフレームは 0 で埋めて push する */
```
`mrl_enc_config`(`mrl_enc_default_config` で既定値)で探索の幅を変えられます。既定値は、評価用の別の 130 発話で品質をほとんど落とさずに絞った値です。

## 手順
半フレーム(20 ms)ごと:
1. 線形予測:サブフレームの中心に 240 sample の Hamming 窓(後半は 10 ms の先読み)、ラグ窓、Levinson、Chebyshev 多項式の根の探索で LSF
2. LSF の量子化:デコーダの移動平均予測(モード 0/1)を裏返した目標に対して、1 段・2 段の上位の候補を組み合わせる。誤差は後半の LSF と、前半(デコーダは前の半フレームとの中点を使う)の LSF の両方で測る
3. 開ループのピッチ:聴感の重み付けをした音声の正規化相関

サブフレーム(10 ms)ごと:

4. 目標:聴感の重み付け W(z) = A(z/0.94)/A(z/0.6) をかけた入力から零入力応答を引く
5. ピッチ:開ループの候補の前後の整数のラグを、分母は補間フィルタを通した励振の再帰(G.729 と同じ)、分子は正確な適応符号帳で比べ、小数(±1/3)は前後の得点が高い側だけ調べる
6. 固定符号帳:パルスの形をフィルタに通したものを位置をずらして使い、相関の大きい位置だけ組み合わせる。単位パルス 5 + 5 個の区分は、表の行を相関で絞ってから組み合わせる
7. 上位の候補を 128 通りのゲインと比べ、選んだものだけ正確な符号ベクトル(周期強調つき)を作ってゲインを選び直す
8. 選んだパラメータでデコーダの状態を進める

## MCU での実測
テストの音声(LibriSpeech の 4.8 秒、120 フレーム)を符号化して、デスクトップと同じフレームか確かめ、そのフレームを復号した PCM のハッシュも確かめて、
1 フレーム(40 ms)あたりのサイクル数を数えます(`tests/mcu/mcu_test.c`)。

| ボード | エンコーダ | デコーダ | 合計(CPU の割合) | 一致 |
|---|---|---|---|---|
| Arduino Portenta H7(Cortex-M7、400 MHz) | 270 万サイクル(最大 283 万) | 22 万 | 292 万(18%) | フレーム 120/120、PCM 一致 |
| ESP32-WROOM-32(240 MHz、1 コア、コードと表は内部 RAM) | 319 万(最大 333 万) | 38 万 | 357 万(37%、最も重いフレームで 39%) | フレーム 120/120、PCM 一致 |

```
cd examples/esp32 && ./run.sh /dev/cu.usbserial-XXXX    # ESP-IDF 5.4。MRL_PROFILE=1 で段階ごと、MRL_MICRO=1 で部品ごとの計測
tests/mcu/portenta/run_portenta.sh                       # arduino-cli と arduino:mbed_portenta、pyserial
tests/mcu/update_expected.sh                             # エンコーダを変えたら期待値を作り直す
```

ESP32 で効いたこと(最初の版の 1750 万サイクルから 320 万へ):
- 探索の幅を、評価用の発話で品質を見ながら絞る(開ループの 2 つ目のピッチ候補は、調べない方が品質も良かった。倍ピッチの誤りが減るため)
- ピッチの分母は G.729 と同じ再帰、分子だけ正確に。符号 ↔ ラグは表と算術式で(デコーダの関数は 16 段のビットごとの割り算)
- 固定符号帳の相関は H^T x と形の内積で。ゲインは、フィルタを通したパルスの形を足し合わせた近似で比べ、選んだものだけ正確に
- 割り算を避ける(ESP32 の浮動小数の割り算はソフトウェア)。内積の形にして累積を 4 本に分ける
- エンコーダだけ積和を 1 命令(`-ffp-contract=fast`、`madd.s`)にする
- デコーダの固定小数点:40 ビットの巻き戻しの省略と MAC16(ビット一致のまま、デコーダ単体で 63 万 → 38 万サイクル)
- コードと表を内部 RAM に置く
